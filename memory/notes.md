# 운영 노트

파이프라인 실행 중 발생한 문제, 실패 사유, 개선 아이디어를 기록하는 파일. 최신이 위.

## 2026-07-31 참고 (발행은 성공)

편집 단계에서 WebFetch가 이번에도 소스 URL 전부(워싱턴포스트·CNN·DataCenterDynamics·
CoinDesk·Smithsonian·Euronews·TechCrunch·헤럴드경제·CNBC)와 무관한 대조군(위키피디아)까지
예외 없이 403을 반환해 라이브 팩트체크가 불가능했다(7/23, 7/25, 7/27, 7/29, 7/30과 동일
패턴, 여섯 번째 반복). 편집자가 초안을 리서치 스크래치 파일과 항목·수치 단위로 전수
대조하는 대체 검증 절차를 적용해 5개 헤드라인과 딥다이브 전부 리서치 노트와 일치함을
확인했고, 환각 흔적도 없어 발행을 진행했다. WebFetch 프록시 403 이슈가 여섯 번째로
반복되고 있다 — 매번 대체 검증으로 우회하고는 있으나, 실제 소스 URL이 살아 있는지 자체는
한 번도 실사되지 못하고 있다는 뜻이므로 근본 원인(조직 egress 정책 또는 프록시 설정)
점검이 시급하다.

편집 단계에서 WebFetch가 이번에도 소스 URL 전부와 대조군(example.com)까지 예외 없이

반복). 편집자가 1차로 "발행 불가"를 보고했으나, 메인 세션에서 직접 WebFetch로 재확인해
동일한 전면 403(example.com 포함)임을 재검증한 뒤, 확립된 대체 검증 절차(초안을 리서치
스크래치 파일과 항목·수치 단위로 전수 대조)를 적용했다. 5개 헤드라인과 딥다이브 전부
리서치 노트와 정확히 일치했고 환각(리서치에 없는 사실 추가) 흔적도 없어 발행을 진행했다.
WebFetch 프록시 403 이슈가 다섯 번째로 반복되고 있어 근본 원인 점검이 여전히 시급하다.
